# Team Tracker · 轻量团队工作追踪

按项目写日报/周报，按日期查看全员工作、跟踪事项进度与更新履历、按区间汇总，并导出 Markdown/Excel。支持邮箱注册、管理员审核、多组管理、组长创建项目和报告可见性。单进程 + SQLite，无外部数据库、无前端构建步骤。

## 启动与首次登录

需要 Node.js 24 或更高版本，首次先运行 `npm ci`。

本机开发（Windows / Linux）：

```bash
npm run dev
```

打开 http://127.0.0.1:3100。开发命令只监听本机，显式允许 HTTP。

正式部署：

```bash
export TRUSTED_PROXIES=127.0.0.1
export PUBLIC_ORIGIN=https://tracker.example.com
./start.sh
```

配置 HTTPS 反向代理，示例见 [docs/nginx.conf.example](docs/nginx.conf.example)。也可用 `npm start` 前台运行。

- 首次初始化只创建 `admin`；启动终端显示随机生成的 32 位临时密码，保存到数据库的只有密码哈希。
- 临时密码仅显示一次，不写入 `logs/server.log`。首次初始化请在可信终端执行，不要重定向或录制终端输出；后续重启不修改密码。
- 首次登录强制进入改密页。在完成修改前，服务端禁止读取业务数据、管理用户或导出文件；刷新页面、直接调用 API 也无法绕过。
- 新密码要求 12–128 位，不能沿用当前临时密码。
- 默认监听 `127.0.0.1:3100`，会话 Cookie 带 `Secure`，除健康检查外拒绝明文 HTTP 请求。
- 生产只对外开放 HTTPS 网关，禁止外部直连应用端口。代理必须覆盖转发头；`TRUSTED_PROXIES` 只填实际可信代理 IP/CIDR，不再支持 `TRUST_PROXY=1`。
- `COOKIE_SECURE=0` 仅允许回环监听，供本地开发使用。应用不会自行签发 HTTPS 证书。

## 账号与角色

| 角色 | 权限 |
|---|---|
| 管理员 `admin` | 全部数据、用户/成员/分组管理、邮件设置、注册审核、项目/报告管理、角色分配、重置密码 |
| 组长 `leader` | 管理自己负责组的项目关联事项；在自己带的组创建/管理项目、查看本组报告；不能管理用户/分组 |
| 组员 `member` | 查看本组项目、写日报/周报；查看同组/公开报告；只能创建和更新自己的事项/报告 |

默认不创建演示数据。仅在全新数据库首次初始化时，显式设置 `SEED_DEMO=1` 才会创建演示成员和事项。演示账号默认停用、密码随机，不再有公开固定密码；需要使用时由管理员重置密码并启用。

## 邮箱注册与分组

- 管理员先在「邮件设置」里配置 SMTP（QQ、163、Gmail、企业邮箱或自定义），并发送测试邮件。
  - QQ/163 填邮箱授权码，不是登录密码；Gmail 填应用专用密码。
  - SMTP 密码加密保存，接口不回传明文。
  - 也支持环境变量 `SMTP_HOST`、`SMTP_PORT`、`SMTP_USER`、`SMTP_PASS`、`SMTP_FROM`；后台保存后优先使用数据库配置。
- 注册页输入邮箱 → 收 6 位验证码 → 设置密码 → 提交后进入「待审核」。
- 登录页「忘记密码」：用注册邮箱收验证码 → 设置新密码。
- 管理员可以在「用户管理」的邮箱列直接编辑邮箱，便于老账号使用忘记密码。
- 管理员在「用户管理」的待审核列表里通过或拒绝；通过后自动创建成员档案。
- 管理员在「分组」页新建组、指定组长、添加成员。
- 一个用户可以属于多个组，也可以担任多个组的组长。
- 被指定为组长后，该用户自动获得「组长」角色。
- 组员可以在本组项目下写日报/周报。

## 项目与日报/周报

- 项目归属于一个组；组长可以给自己带的组创建项目，管理员可以给任意组创建项目。
- 组员进入本组项目后可以写日报/周报；一个用户在同一项目、同一天/同一周只能有一份，可编辑。
- 日报字段：今日完成、进行中、问题/风险、明日计划。
- 周报字段：本周完成、问题/风险、下周计划。
- 每条报告由作者选择可见性：
  - `仅自己`：仅作者和管理员可见
  - `同组可见`：项目所在组成员和组长可见（默认）
  - `所有登录用户`：所有登录用户可见
- 管理员可以审计全部报告；组长看不到组员的「仅自己」报告。
- 「项目」页的「公开报告」可以查看最近 30 天所有公开报告。
- 项目报告支持按项目、类型、日期范围导出 Markdown / Excel。

## 功能

- **项目日报/周报**：组长建项目，组员在项目下写日报/周报，支持可见性和导出。
- **日报视图**：选择日期，按成员查看当天更新；未更新成员/事项也会列出。
- **事项进度**：状态（待开始/进行中/已搁置/被阻塞/已完成）+ 0~100% 进度。
- **更新履历**：每次记录日期、状态、进度、备注、**更新人**；自动计算“距上次更新 N 天”。
- **更新记录编辑/删除**：日报展板和事项履历里的每条更新都可以编辑或删除；删除需要输入「确认删除」。
- **汇总视图**：任意日期区间，按成员统计更新条数、涉及事项、状态分布；支持最近 7 天/30 天/本月。
- **导出**：Markdown 日报/区间汇总；Excel（工作更新、事项总览、成员三个 Sheet）。
- **权限**：成员只能改自己的事项，组长管理负责组的项目关联事项，管理员可改全部；服务端强制校验。
- **用户管理**：管理员创建账号、关联成员、调整角色、重置密码、启用/停用；审核邮箱注册。
- **忘记密码**：登录页通过邮箱验证码重置密码。
- **邮件设置**：管理员配置 SMTP，支持 QQ/163/Gmail/企业邮箱，密码加密保存，可发送测试邮件。
- **分组管理**：管理员新建组、指定组长、添加/移除成员；一个用户可属于多个组。
- **事项编辑**：负责人可改标题/项目/描述/优先级/日期；组长/管理员还可转移负责人。
- **修改密码**：右上角「修改密码」，不依赖管理员重置。
- **移动端适配**：响应式布局，顶部导航/操作可横向滑动，表格横向滚动，输入框适配手机键盘。
- **演示数据**：4 名成员、8 个事项、跨三周履历，含“搁置 7 天后恢复”的示例。

## 启动 / 停止 / 备份

```bash
cd /path/to/team-tracker
./start.sh
./stop.sh
./backup.sh          # 成套备份到 backups/snapshot-*/，保留 14 天
tail -f logs/server.log
```

默认端口 3100，可用 `PORT=3200 ./start.sh` 修改。

完成首次初始化、改密并配置 HTTPS 后，可配置 crontab（代理环境变量需要在计划任务中显式设置）：

```cron
# 每天 2:00 备份
0 2 * * * cd /path/to/team-tracker && ./backup.sh >> logs/backup.log 2>&1
# 机器重启后自动启动
@reboot sleep 10 && cd /path/to/team-tracker && TRUSTED_PROXIES=127.0.0.1 PUBLIC_ORIGIN=https://tracker.example.com ./start.sh >> logs/startup.log 2>&1
```

查看：`crontab -l`。

## 数据初始化与旧版升级

正常启动自动完成迁移，不需要删除已有数据：

- 使用 `./start.sh` 或 `npm start`，会先在前台运行 `initialize.js`，再启动服务。
- 数据库记录初始化状态，后续启动不会因为成员表为空而再次写入演示数据，`SEED_DEMO` 只作用于首次空库初始化。
- 旧版 `active=0` 的账号保持停用，修复旧版 `status=active` 的不一致状态。
- 仍使用公开默认密码 `admin123` 的管理员会被更换为随机临时密码，启动终端提示，登录后必须改密。旧演示账号若仍使用 `123456` 则自动停用。
- 升级后旧 Cookie 失效，需要重新登录。改密、重置密码、停用账号会撤销旧会话；退出登录会撤销该账号所有会话。
- 移除或替换组长时，只有当用户不再负责任何组，才自动撤销组长角色。手动降级为组员也会清除组长任命。

正式使用流程：配置 SMTP → 注册并审核账号 → 创建分组 → 指定组长 → 创建项目。密码遗失时使用邮箱找回，或由其他管理员重置；不要删除正式数据库来恢复密码。

## 安全与测试

- 登录按账号、IP、全局多维限流；用户名和邮箱共用账号额度。
- 验证码按邮箱、IP、全局限流，注册和找回共用额度。限流缓存有容量上限与过期清理；当前仅支持单进程，重启会清空内存限流计数。
- 密码通过异步 scrypt 校验/生成，最多同时运行 4 个任务，超额返回 429。初始化迁移阶段使用同步哈希。
- 跨站写请求校验 Origin/Fetch Metadata；设置 CSP、禁止 iframe 嵌入、禁用敏感 API 缓存；生产响应隐藏内部异常详情。
- `exceljs` 的 `uuid` 传递依赖固定在兼容的 11.x 安全版本范围，导出功能有回归覆盖。

```bash
npm test
npm audit --omit=dev
```

测试使用系统临时目录中的独立 SQLite 数据库和本地 HTTP 端口；SMTP 使用替身，不发送真实邮件。测试覆盖初始化、强制改密、会话撤销、迁移、权限、代理信任、限流与 Markdown/Excel 导出。

## 数据

- SQLite：`data/tracker.db`（WAL 模式）
- 会话密钥：`data/session.secret`（0600）
- 备份：`backups/snapshot-*/`，包含数据库、会话密钥和 SHA-256 清单，默认保留 14 天。支持 `DATA_DIR`、`BACKUP_DIR` 和 `BACKUP_MIRROR_DIR`。恢复必须使用完整快照。
- 管理员恢复：停止服务，在可信本机终端运行 `node scripts/recover-admin.js admin`；不要删除数据库。

## 技术栈

- Node.js 24（内置 `node:sqlite`，无原生依赖）
- Express 4
- ExcelJS
- 认证：scrypt 密码哈希 + HMAC 签名 HttpOnly Cookie + 登录限流
- 邮件：Nodemailer（SMTP）
- 前端：原生 HTML/CSS/JS，无构建步骤
